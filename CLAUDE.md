# CLAUDE.md — Boardroom

## Project summary

**Boardroom** is a multi-user web app that tracks Indian listed companies' public filings (BSE/NSE): earnings-call transcripts, quarterly results, announcements. Users sign up, build a watchlist, and use:

1. **Promise tracker** — extract management guidance/promises from transcripts and check them against later results (kept / missed / delayed / pending).
2. **Ask-the-filings** — a Q&A agent that answers questions across a company's documents with page-level citations.
3. Later: red-flag detection, quarterly briefs, alerts.

Company data (filings, promises, checks) is **shared** across all users. Watchlists and question history are **per user**.

This is a **learning project**. The developer (Hayat) is hand-writing all AI/agent logic to learn it. Claude Code builds the surrounding full-stack scaffolding only.

## Tech stack

- **Monorepo:** pnpm workspaces + Turborepo. Package scope `@boardroom/*`.
- **Language:** TypeScript everywhere, strict mode.
- **Frontend:** `apps/web` — React + Vite, React Router, TanStack Query, Tailwind CSS, shadcn/ui (custom design system in `src/index.css`). (Not Next.js.)
- **Backend:** `apps/api` — Node.js + Express, Zod for request validation.
- **Auth:** **Better Auth** with email + password, session cookies (httpOnly), Drizzle adapter. Mounted in Express. Email verification and password reset can be stubbed (log the link to console) in dev.
- **Database:** PostgreSQL (16+; local dev runs 17) with pgvector; **Drizzle ORM** + drizzle-kit migrations. `packages/db` holds schema and client.
- **Jobs:** pg-boss (Postgres-based queue).
- **File storage:** **S3 from day one — nothing stored on local disk.** AWS S3 only. Use `@aws-sdk/client-s3` through plain functions in `services/storage.ts` (upload, download, delete, presigned GET URL). Separate dev bucket. For PDF processing, stream the object from S3 into memory and discard after; never persist files locally. Object keys: `filings/{companyId}/{filingId}.pdf`. Bucket stays private; frontend opens source PDFs via short-lived presigned URLs.
- **PDF text:** pdf-parse for digital PDFs (OCR out of scope for now).
- **LLM provider:** the `callLLM()` function in `apps/api/src/llm/llm.ts`; Claude Code may implement the thin HTTP client but NOT prompts or agent logic.
- **Local dev:** local Postgres install with pgvector (no Docker). One-time setup: `pnpm db:setup` (runs `scripts/setup-local-db.sql` as the postgres superuser).
- **Config:** `.env` with `DATABASE_URL`, `LLM_API_KEY`, `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `VITE_API_URL`. Provide `.env.example`.

## Data model (Drizzle)

- **Auth tables** — generated by Better Auth (user, session, account, verification). Add `role` (user|admin) to user.
- `companies` — id, name, bse_code, nse_symbol, sector.
- `watchlist_items` — id, user_id, company_id, created_at (unique user_id + company_id).
- `filings` — id, company_id, source (bse|nse|manual), category, title, filed_at, url, storage_key (S3 object key), status (new|processed|failed), uploaded_by (user_id, nullable).
- `document_pages` — id, filing_id, page_number, text.
- `chunks` — id, filing_id, page_number, content, embedding vector(1536) nullable.
- `promises` — id, company_id, source_filing_id, source_page, speaker, statement, metric, target_value, deadline, created_at.
- `promise_checks` — id, promise_id, checked_against_filing_id, status (kept|missed|delayed|pending|unclear), evidence, evidence_page, checked_at.
- `questions` — id, user_id, company_id, question, answer, citations jsonb, created_at.
- `llm_calls` — id, user_id nullable, purpose, model, input_tokens, output_tokens, cost_usd, latency_ms, request jsonb, response jsonb, created_at.

## Access rules

- All `/api/*` routes except auth require a logged-in user (`requireAuth`).
- Uploading/processing filings and running promise checks: **admin only** (`requireAdmin`). Normal users read shared data.
- Users see only their own watchlist and question history.
- Rate limit `POST /ask` per user (e.g. 20/day) to control LLM cost.

## API endpoints

- `/api/auth/*` — Better Auth handlers (sign up, sign in, sign out, session).
- `GET /api/me` — current user.
- `GET /api/companies` — list/search companies.
- `GET /api/companies/:id` — company detail + counts.
- `GET /api/watchlist`, `POST /api/watchlist` `{ companyId }`, `DELETE /api/watchlist/:companyId`.
- `GET /api/companies/:id/filings` — filings list.
- `GET /api/filings/:id/url` — presigned URL to view the source PDF.
- `POST /api/companies/:id/filings/upload` — admin; manual PDF upload straight to S3.
- `POST /api/filings/:id/process` — admin; stream PDF from S3 → page text → `document_pages` + `chunks`, then enqueue promise extraction (HAYAT stub).
- `GET /api/companies/:id/promises` — promises with latest check status.
- `POST /api/companies/:id/promises/check` — admin; calls HAYAT stub.
- `POST /api/companies/:id/ask` — body `{ question }`; calls `answerQuestion()` stub; stores per user; returns answer + citations.
- `GET /api/questions` — current user's question history.
- `GET /api/llm-calls` — admin; recent LLM call logs.
